# CLAUDE.md — инструкции для Claude Code на этом проекте

## Правило "пропуски и нехватки"

**Не заявлять фичу/фикс как законченный, пока не проверено:**

1. **Все зависимые файлы и конфиги реально бандлятся.** Если код использует бинарь — убедиться что бандлится не только сам бинарь, но и все его runtime-файлы (DLL, tessdata/configs, Ghostscript Resource/Init, fonts, ICC-профили, plugins и т.д.).
2. **CI-шаг не только собирается, но и запускается на реальных данных.** "Компилируется" ≠ "работает". После сборки — обязательный smoke-test на свежеустановленной копии.
3. **YAML / PowerShell / shell-скрипты проверены парсером** перед коммитом:
   - `python -c "import yaml; yaml.safe_load(open('...'))"` для YAML
   - `pwsh -NoProfile -Command "try { ... } catch { ... }"` для PowerShell heredoc'ов
4. **Новый код с внешними зависимостями проверен end-to-end**, а не только unit-тестами с моками. Моки ловят логику, не ловят "зависимость не установлена".
5. **Класс багов, а не один баг.** Если нашёл один missing file — проверить ВСЁ того же класса (другие бинари, другие бандлы). История этого проекта:
   - `tessdata/configs/` — 3 дня production blocker
   - `Ghostscript Resource/Init/` — следующий, поймали только проактивным аудитом
   - CLI-routing — поймали только когда smoke-test упал

## Правило "последовательность проверки"

Перед тем как сказать "готово":

- [ ] ruff check
- [ ] pytest на релевантных unit-тестах
- [ ] YAML/скрипты валидируются парсером
- [ ] Для CI-изменений — прогнать в голове каждый шаг workflow'а: "что реально произойдёт, что может отсутствовать"
- [ ] Для бандлинга — распаковать воображаемый результат сборки и спросить: "этого достаточно чтобы запуститься на чистой машине?"
- [ ] Если коммит добавляет фичу с внешней зависимостью — сразу писать smoke-тест, который её использует

## Привычка проекта

Пользователь на Windows, цель приложения — работать на Windows у конечных пользователей. Linux-CI нужен только как быстрый/дешёвый runner для lint и простых проверок. Всё, что касается реальной работы приложения, должно быть подтверждено на Windows-runner'е.
